# امید — همراه همیشگی دانش‌آموز (Flutter)

اپ اندروید برای دانش‌آموزان + پنل مشاور؛ بک‌اند: Worker جوجو (`/api/...`).

## قفل نمایش برنامه‌ی روزانه (نسخه‌ی ۱.۴.۱)
- در صفحه‌ی «برنامه»، فقط برنامه‌ی تاریخ جاری تهران نمایش داده می‌شود؛ روزهای دیگر در نوار هفتگی با آیکون قفل و ظاهر کم‌رنگ دیده می‌شوند و با لمسشان پیام زمان بازشدن نشان داده می‌شود.
- برنامه‌ی هر روز از ساعت **۰۱:۰۰ بامداد همان روز** باز می‌شود. بین ۰۰:۰۰ تا ۰۱:۰۰، برنامه‌ی روز جدید هنوز قفل است.
- صفحه هنگام بازبودن اپ هر ۱۵ ثانیه ساعت را بررسی می‌کند و با برگشت اپ از پس‌زمینه نیز دوباره وضعیت را می‌سنجد؛ در نیمه‌شب داده‌ی روز جدید را تازه‌سازی می‌کند.
- **محدودیت فنی:** این نسخه قفل را در رابط کاربری Flutter اعمال می‌کند. چون سورس Worker جوجو در این مخزن نیست، این قفل هنوز در API/سرور enforce نمی‌شود و با تغییر دستی ساعت گوشی یا درخواست مستقیم API قابل دورزدن است. برای قفل امنیتی باید همین قانون در Worker نیز اعمال شود.

## بیلد APK
1. پروژه را در یک ریپوی GitHub بگذار و push کن.
2. Actions ← Build APK ← Run workflow. خروجی‌ها:
   - `omid-apk-arm64`: برای گوشی‌های امروزی (حدود ۲۰ مگابایت)
   - `omid-apk-armv7-old-phones`: فقط برای گوشی‌های خیلی قدیمی
   - `omid-symbols`: برای خواندن خطاهای obfuscate شده (نگهش دار)
3. بیلد از روی یک `flutter create` تازه (اندروید) + همین `lib/` و `pubspec.yaml` ساخته می‌شود و `tool/patch_android.py` مجوزها، سرویس پخش، امضا و کوچک‌سازی را اضافه می‌کند.
4. فونت Vazirmatn خودکار از npm دانلود می‌شود. اگر فایل‌های `assets/fonts/Vazirmatn-*.ttf` را خودت در ریپو بگذاری، دانلود رد می‌شود.

## امضای ثابت (یک بار)
۱. روی کامپیوتر:
```
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```
۲. فایل `upload-keystore.jks` را در دو جای امن نگه دار (گم شود، دیگر آپدیت‌پذیر منتشر نمی‌کنی).
۳. تبدیل به Base64 (خروجی را کامل کپی کن):
   - لینوکس: `base64 -w0 upload-keystore.jks`
   - مک: `base64 -i upload-keystore.jks | tr -d '\n'`
   - ویندوز (PowerShell): `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks"))`
۴. GitHub ← Settings ← Secrets and variables ← Actions، این ۴ مورد:
   `KEYSTORE_BASE64`، `KEYSTORE_PASSWORD`، `KEY_ALIAS` (مثلاً `upload`)، `KEY_PASSWORD`.

تا وقتی این‌ها نباشند، بیلد با کلید debug امضا می‌شود و در لاگ هشدار می‌دهد. شماره‌ی `versionCode` از `github.run_number` می‌آید.

## آدرس سرور
آدرس Worker در `lib/core/config.dart` به‌صورت رمزشده (معکوسِ base64) است و در هیچ‌جای رابط اپ نمایش داده نمی‌شود. برای تغییر: base64 آدرس را بگیر، رشته را معکوس کن و در `_u` بگذار.

## رسانه (موزیک و ویدیو) روی Workers KV
1. Cloudflare ← Workers & Pages ← KV ← Create namespace (مثلاً `omid-media`).
2. Worker ← Settings ← Bindings ← Add ← KV namespace ← نام متغیر **`MEDIA_KV`**.
3. `jojo-worker.js` جدید را deploy کن. اگر R2 هم با نام `MEDIA` وصل باشد آن اولویت دارد.
4. هر فایل حداکثر ۲۵ مگابایت (محدودیت KV). موزیک ۲–۸ مگابایت و ویدیوی تمرکز ۱۰–۱۵ مگابایت (۷۲۰p، بدون صدا) مناسب است.
5. از پنل مشاور ← رسانه آپلود کن.

## انیمیشن‌ها (lottie)
فایل‌ها در `assets/lottie/`: `intro` (اولین ورود)، `gradient_bg` (پس‌زمینه‌ی مات ورود)، `loading`، `error_404`، `happy`، `verified`، `ai_abstract`. مسیرها در `lib/theme/lottie_views.dart`.

## فرض‌هایی که باید با Worker واقعی چک شوند
- `POST /report`: فیلدهای `slept` و `distractions` به‌صورت `1/0` فرستاده می‌شوند (`slept=1` یعنی کافی خوابیده).
- `GET /admin/students` هم آرایه و هم `{students:[...]}` را می‌پذیرد؛ پاسخ ساخت دانش‌آموز: `password` در ریشه یا داخل `student`.
- `last_seen` و `live_since` هم epoch (ثانیه/میلی‌ثانیه) و هم ISO را می‌پذیرند.
- `started_at` / `ended_at` در `/focus/session` به‌صورت ISO-8601 UTC.

## قانون اولویت‌ها (سمت اپ)
- اولویت هر پارت = جای آن در فهرست روز (۱ تا ۵)؛ ۱ تا ۴ اصلی، از ۵ به بعد اختیاری. منطق در `lib/core/priority.dart`.
- اپ این کلیدهای اختیاری `GET /plan` را می‌خواند (نبودنشان یعنی ترتیب اجباری روشن و بدون استثنا): `force_order` (bool)، `unlocked` (آرایه‌ی شماره‌ی اولویت‌های بازشده توسط مشاور)، `skipped` (ردشده‌ها).
- `carried`، زمان «تموم شد» و «درست‌ها معلوم است یا نه» فعلاً فقط محلی‌اند. وقتی Worker پذیرفتشان، `Config.sendPriorityFields` را `true` کن تا `priority/status/carried/done_at` هم به `/progress` بروند.
- **قفل هنوز فقط در اپ اعمال می‌شود.** اعمال در سرور (رد `done` برای اولویتی که قبلی‌هایش تمام نشده) به کد Worker نیاز دارد.

## ساخته نشده
- push واقعی (FCM)؛ یادآوری‌ها اعلان محلی‌اند (۷:۰۰ صبح و ۲۱:۳۰ شب).
- ویرایش عنوان رسانه از پنل ادمین (فقط آپلود/حذف).

## آفلاین، همگام‌سازی ۶ ساعته، امنیت و آپدیت (نسخه‌ی ۱.۲.۰)

### کار آفلاین
- **نوشتن:** پیشرفت، گزارش شبانه و جلسه‌ی اتاق تمرکز اول روی گوشی ذخیره می‌شود و در `OfflineQueue` می‌ماند. فقط وقتی حذف می‌شود که سرور «ok» بدهد. خطای موقت (اینترنت، ۵xx، ۴۲۹، ۴۰۱، ۴۰۳) هیچ‌وقت داده را دور نمی‌ریزد؛ خطای دائمی به «صندوق خطا» (`offline_dead`) می‌رود. هر مورد با شناسه‌ی دانش‌آموز ثبت می‌شود و با حساب دیگر فرستاده نمی‌شود. خروج از حساب صف را پاک نمی‌کند.
- **خواندن:** جواب `/plan`، `/stats`، `/music`، `/focus/videos` در `Api.getC` کش می‌شود؛ بدون اینترنت آخرین نسخه‌ی کش‌شده نمایش داده می‌شود (نوار «آفلاین هستی…»). برنامه‌ی ۱۴ روز آینده پیش‌دریافت می‌شود تا بعد از نیمه‌شب هم آفلاین کار کند.
- موزیکی که یک بار پخش شده روی گوشی کش می‌شود (`MediaCache`).

### همگام‌سازی هر ۶ ساعت (`lib/core/sync_service.dart`)
- «همگام» = صف خالی شد + سرور جواب داد (`GET /me`).
- محرک‌ها: شروع اپ، برگشت به اپ، وصل شدن اینترنت (`connectivity_plus`)، heartbeat هر ۶۰ ثانیه، و کار پس‌زمینه‌ی `WorkManager` هر ۶ ساعت (فقط وقتی اینترنت هست).
- بیش از ۶ ساعت بدون همگام‌سازی: نوار هشدار در همه‌ی تب‌ها + اعلان (شناسه‌ی ۳؛ بعد از هر همگام‌سازی ۶ ساعت جلو می‌رود). **قفل نمی‌کند** و داده پاک نمی‌شود.
- کار پس‌زمینه روی HyperOS/MIUI ممکن است توسط محدودیت باتری کشته شود؛ در «باتری ← بدون محدودیت» و «شروع خودکار» برای اپ را روشن کنید. اگر کشته شد، چیزی از دست نمی‌رود: داده روی گوشی می‌ماند و با اولین باز شدن اپ ارسال می‌شود.
- توکن ورود هفته‌ای یک بار با `POST /refresh` تمدید می‌شود (نیاز به Worker جدید).

### امنیت
- توکن در `flutter_secure_storage` (Keystore). فقط HTTPS (در کد و manifest). بکاپ ابری/adb خاموش.
- Worker: توکن‌ها با تغییر رمز دانش‌آموز باطل می‌شوند (`pwv`)، حداقل رمز ۶ نویسه، سقف ۱۰۰ کیلوبایت برای بدنه‌ی JSON، قفل ۱۰ دقیقه‌ای بعد از ۸ رمز اشتباه از یک IP (از قبل).
- رمز دانش‌آموز در Worker فقط به‌صورت هش HMAC ذخیره می‌شود.

### آپدیت بدون از دست رفتن داده
1. **امضای ثابت الزامی است** (بخش «امضای ثابت» بالا). بدون آن هر بیلد با کلید debug متفاوت ساخته می‌شود و اندروید آپدیت را رد می‌کند؛ مجبور می‌شوی اپ را پاک کنی و همه‌ی داده‌های محلی (از جمله ارسال‌نشده‌ها) می‌رود.
2. نام پکیج (`com.jojo.study_companion`) هرگز عوض نشود.
3. ABI عوض نشود (arm64 ← arm64). `versionCode` با `--split-per-abi` برای هر ABI فرق می‌کند و برگشت از arm64 به armv7 «کاهش نسخه» حساب می‌شود.
4. داده‌ی محلی نسخه‌دار است (`LocalMigrations`، کلید `schema_v`). هر وقت شکل ذخیره‌ی محلی عوض شد یک مرحله به `local_migrations.dart` اضافه کن؛ کلیدهای قدیمی را حذف نکن.
5. Worker: فقط `CREATE TABLE IF NOT EXISTS`/`ALTER` (هیچ `DROP`). دیتابیس D1 مستقل از اپ و آپدیت Worker است.
6. بار اول که از بیلد debug به بیلد امضای ثابت می‌روی، یک بار پاک‌کردن اپ لازم است: قبلش در «تنظیمات» مطمئن شو «منتظر ارسال: ۰ مورد».
