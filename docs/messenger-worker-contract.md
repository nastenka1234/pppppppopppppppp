# قرارداد پیام‌رسان امید برای Worker «جوجو»

این ZIP فقط کلاینت Flutter است و سورس Worker در آن وجود ندارد. رابط اپ برای مسیرهای زیر آماده شده؛ تا زمان پیاده‌سازی این مسیرها در Worker، پیام‌رسان قادر به تبادل واقعی پیام بین دو حساب نیست.

## ۱) فهرست گفتگوهای مشاور

`GET /api/messages/threads`

فقط نقش `admin` مجاز است. پاسخ:

```json
{
  "threads": [
    {
      "student_id": "student-id",
      "name": "نام دانش‌آموز",
      "last_message": "متن آخرین پیام یا عنوان فایل",
      "updated_at": "2026-11-16T10:30:00Z",
      "unread": 2
    }
  ]
}
```

## ۲) خواندن پیام‌ها

`GET /api/messages`

- دانش‌آموز: شناسه‌ی دانش‌آموز باید فقط از توکن استخراج شود؛ query ارسالی کاربر نباید امکان خواندن گفتگوهای دیگر را بدهد.
- مشاور: باید `?student=<student_id>` بفرستد و فقط گفتگوهای همان دانش‌آموز را ببیند.

پاسخ:

```json
{
  "messages": [
    {
      "id": "message-id",
      "type": "text",
      "text": "سلام",
      "attachment_url": "",
      "attachment_name": "",
      "mime_type": "",
      "created_at": "2026-11-16T10:30:00Z",
      "sender_role": "student",
      "mine": true
    }
  ]
}
```

مقادیر `type`: `text`، `image`، `audio`، `document`. مقدار `mine` باید نسبت به کاربر فعلی محاسبه شود.

## ۳) آپلود پیوست

`POST /api/messages/upload` با `multipart/form-data` شامل `file` و `kind`.

- حداکثر اندازه: ۲۵ مگابایت.
- نوع‌های مجاز: تصویرهای jpg/jpeg/png/webp، صدای m4a/aac و سند PDF.
- احراز هویت با همان Bearer token فعلی.
- فایل در فضای رسانه‌ی فعلی پروژه (طبق تصمیم پروژه، Workers KV) ذخیره شود.
- URL باید با احراز هویت قابل دریافت باشد و برای مسیرهای نسبی از الگوی `/media/messages/<id>` استفاده کند؛ اپ آن را از طریق `Api.abs` به آدرس کامل تبدیل می‌کند.

پاسخ:

```json
{
  "url": "/media/messages/file-id",
  "name": "weekly-report.pdf",
  "mime_type": "application/pdf",
  "size": 24567
}
```

## ۴) ارسال پیام

`POST /api/messages` با JSON:

```json
{
  "type": "document",
  "text": "",
  "attachment_url": "/media/messages/file-id",
  "attachment_name": "omid-weekly.pdf",
  "mime_type": "application/pdf",
  "size": 24567,
  "student_id": "student-id"
}
```

`student_id` برای ارسال از پنل مشاور الزامی است و برای حساب دانش‌آموز حذف می‌شود. Worker باید هویت فرستنده را فقط از توکن تعیین کند، شناسه‌ی دانش‌آموز را برای دانش‌آموز از توکن استخراج کند، دسترسی مشاور را محدود به حساب‌های مجاز نگه دارد و پیام را با شناسه‌ی گفتگو ذخیره کند.

## ۵) مدل ذخیره‌سازی پیشنهادی

جدول D1 با ستون‌های حداقلی:

- `id`, `student_id`, `sender_role`, `sender_id`
- `type`, `text`, `attachment_key`, `attachment_name`, `mime_type`, `size`
- `created_at`, `read_at`

برای فهرست گفتگوها، آخرین پیام و تعداد پیام‌های خوانده‌نشده بر اساس `student_id` تجمیع شود. فایل‌ها در KV قرار می‌گیرند؛ اطلاعات پیام و متادیتا در D1.

## ۶) نکات ایمنی و محصول

- دانش‌آموز نباید با تغییر `student_id` به گفتگوی دانش‌آموز دیگری دسترسی بگیرد.
- مشاور نیز فقط به حساب‌های زیرمجموعه‌ی مجاز خود دسترسی داشته باشد.
- برای `GET /media/messages/<id>` احراز هویت و کنترل تعلق فایل به گفتگو انجام شود.
- متن پیام‌ها و نام فایل‌ها قبل از نمایش escape شوند؛ نوع فایل فقط از پسوند اعتماد نگیرد و MIME واقعی/امضای فایل بررسی شود.
- آپلود و ارسال پیام دو مرحله‌ی جدا هستند؛ فایل آپلودشده‌ی بدون پیام باید با job پاک‌سازی دوره‌ای جمع شود.
- API فهرست گفتگو و پیام‌ها در اپ هر ۸ ثانیه هنگام باز بودن پنجره به‌روزرسانی می‌شود.

## ۷) فایل‌های صوتی و خوانده‌شدن پیام

- پاسخ فایل صوتی باید `Content-Type: audio/mp4` (برای M4A) و `Content-Length` صحیح داشته باشد و درخواست‌های HTTP `Range` را پشتیبانی کند تا مدت و پخش مرحله‌ای ویس در Android درست کار کند.
- `GET /api/messages` هنگام بازشدن گفتگو، پیام‌های دریافتیِ همان گفتگو را `read_at` کند؛ شمارنده‌ی `unread` در پاسخ فهرست گفتگوها بر همین اساس محاسبه شود.
